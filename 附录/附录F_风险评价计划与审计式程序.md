# 附录 F：金融 Agent 风控专项评价计划（方法工具）

> 此处不重复定义审计理论。第23–26章解释方法缘由；本附录展示将方法转化为风控人员工作安排时需要哪些字段和决策。

## F.1 评价计划

| 阶段 | 主要活动 | 形成的材料 | 何时升级 |
|---|---|---|---|
| 业务识别 | 确认真实能力、资金影响、数据分类和自主性 | Agent资产/能力登记、资金流与数据流图 | 发现未登记写权限 |
| 威胁识别 | 梳理攻击者、可控入口、信任边界 | 风险场景与损失路径 | 未授权资金流可达 |
| 控制确认 | 将风险映射至具备所有者的硬控制 | 风险控制矩阵、策略版本清单 | 无控制所有者或例外批准 |
| 设计评价 | 查明控制是否覆盖真实执行接口 | 数据契约、权限与状态机评审 | 模型可直接绕开执行网关 |
| 运行评价 | 理解关键控制如何在运行中生效 | 控制判定记录、告警及变更追溯 | 关键控制未运行或可被绕过 |
| 结果核验 | 使用独立来源核对交易、资金和客户数据 | 对账差异、重算依据、结论 | 出现无法解释的差异 |
| 残余风险 | 定级、报告、整改、复核和恢复 | 决策记录、期限、负责人与后续监控 | 存在无批准的重大风险接受 |

## F.2 从一个风险写出“审计式”验证问题

风险陈述：Research Agent 的受污染财报内容导致未授权交易。

1. **控制目标**：没有独立授权、有效风险预算和真实账户状态，不得形成外部订单副作用。
2. **预防控制**：不可信文档隔离、能力令牌、策略网关、限额与审批绑定。
3. **发现控制**：关联 `trace_id` 的工具请求、策略判定及实际交易回执；独立核对异常账户。
4. **设计判断**：策略网关是否覆盖全部写接口和备用执行链路。
5. **控制运行评价**：记录拒绝与批准是否来自经审批的策略版本和可信身份。
6. **结果核验**：从全部权威成交记录反向追溯授权，检查是否漏记、超额或未经批准。
7. **整改恢复**：撤销异常能力、评估已发生敞口、保全证据、完成规则与链路修复，经授权后恢复。

## F.3 几个容易混用的方法

| 方法 | 正确问题 | 不应得出的结论 |
|---|---|---|
| 风险评估程序 | 哪些损失路径需要重点关注？ | 已证明控制有效 |
| 控制设计评价 | 控制在逻辑上能否阻止损失？ | 上线后持续执行正确 |
| 控制运行评价 | 控制是否在预定范围与期间内起作用？ | 资金账必然没有错 |
| 细节核验 | 已执行的每笔交易是否有授权、数量和回执？ | 未检查交易的未来风险为零 |
| 分析性核验 | 风险指标、交易形态是否出现异常？ | 仅凭异常即可认定攻击 |
| 独立证据 | 能否证明数据/授权/动作的来源？ | 任意一条哈希链能保证业务真实 |

## F.4 抽样与重大例外

仅当总体（所有相关执行指令、工具调用、资金和持仓记录）完整且可追溯时才谈抽样。重大金额、权限提升、风险限额变更、异常恢复等可按全量检查；一般事件可按业务风险、时间分层和独立随机方法核验。审计式结论中始终分别列出“已发现问题”和“资料缺失或无法确认”，不能把证据缺失算作通过。

## F.5 处置与复核门槛

业务后果优先：若存在实际资金与客户资产影响，应先限制继续扩大风险，同时保全授权、策略、模型、输入材料、工具和外部回执的证据链；再查明差异、建立临时补偿控制、整改并独立复核。恢复高自主权限之前，须取得风险负责人批准及权威对账结果。风险接受不是简单写“同意”，必须明确期限、范围、最大可能影响与替代措施。
